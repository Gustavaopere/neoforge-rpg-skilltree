# Roadmap de autoria

## Regra transversal
Nenhuma etapa pode exigir assinatura adicional, compra de créditos ou API paga para continuar funcionando.

## Ordem

1. Padronizar fichas de NPC, voz e aparência.
2. Criar briefs visuais dos NPCs principais.
3. Produzir portraits/concepts com ferramenta disponível sem custo incremental e validar assets pela pipeline da Minecraft Mod Factory/Blockbench.
4. Criar corpus de voz e primeiros diálogos versionados em Markdown.
5. Reconciliar entidades e fatos centrais com Grimoire/TTRPG.bot por IDs/proveniência sempre que a conexão estiver disponível.
6. Usar inventário/validadores locais para reduzir duplicatas, placeholders e referências quebradas.
7. Testar MCP/story tools adicionais somente quando resolverem uma necessidade concreta não coberta por Grimoire + GitHub + tooling local; nunca criar segunda Campaign Bible autoritativa.
8. Avaliar Ink/Inky somente quando branching em Markdown deixar de ser suficiente.
9. Avaliar IA in-game apenas depois de toda a campanha base funcionar sem ela.

## Não planejado

- depender de trial como infraestrutura;
- contratar API apenas para autoria;
- duplicar o cânone em duas story bibles;
- substituir Grimoire por serviço externo sem decisão editorial explícita;
- colocar LLM externo como autoridade de runtime.

Cada etapa precisa continuar funcional mesmo que qualquer ferramenta externa opcional seja removida.
